# Memory audit

The audit half of the kit's memory module, in skill form.
Pack-authored for the Muse Setup Kit's Grok profile;
unrehearsed. The platform's stores are legible — dated,
single-sentence, searchable — so audit them; the platform owns
the schema and the history, so audit is all there is.

1. **Inventory.** Search each store and list what it holds, with
   dates: this bot's profile and journal, the account-level user
   profile, and the shared stores. Name the store beside every
   fact. A private fact sitting in the account-level profile —
   readable by every bot on the account — is a finding.
2. **Lint.** Check the inventory for: facts that contradict each
   other; a fact superseded by a later dated fact still standing
   beside it; facts the workspace record contradicts (a journal
   entry claiming work no run-record line supports). Findings
   are candidates, listed with both sides quoted. Decide nothing
   yourself.
3. **Fidelity.** Pick a sample of facts at random and check each
   against its source — a workspace file, the run-record, the
   user's own earlier words. Report each sampled fact as
   confirmed, contradicted, or unverifiable. A fact with no
   checkable source is unverifiable; say so, do not pass over it.
4. **Corrections.** For every finding the user approves, apply
   the platform's only edit: remove the old fact by its exact
   text, then add the corrected fact. Show the remove/add pair
   verbatim in the report. Removal is verified at the search
   layer — search again and show the old text absent and the
   count consistent. Whether the server retains removed facts
   is not inspectable; the report says so rather than claiming a
   deletion it cannot see.
