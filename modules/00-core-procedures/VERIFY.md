# Verify — Module 00: Core Procedures

## At install

- [ ] `OPERATING_PROCEDURES.md` exists; its Local configuration section is
      filled — no `<PLACEHOLDER>` remains anywhere in the file.
- [ ] The autonomy variant from interview Q2 is reflected in §2.
- [ ] The decision queue exists; the template's example item is a comment,
      so the first real item will be #1.
- [ ] Every workstream named in the interview has a `SCOPE.md` with all
      five fields and a `## Closed` section.
- [ ] The main instruction file (or the created `INSTRUCTIONS.md`) carries
      the pointer line to the procedures.
- [ ] `JOBS.md` exists at the workspace root, built from the module's JOBS template (canonical entry format; empty of jobs is fine).
- [ ] The continuity handover exists with a review-by date, in one
      of three states: filled with the user; filled as far as the
      user can take it today — the load-bearing fields complete
      (who picks things up, how to pause the agent), the remainder
      marked not-yet-supplied in the file and its completion
      ledgered as a deferred check; or ledgered whole as a
      deferred check with the user named as its owner. A skeleton
      file created from the template, its unfilled fields marked
      not-yet-supplied, is the normal form of the ledgered-whole
      state — the file's existence does not promote it to the
      middle state; the load-bearing fields decide which state
      it is in. The middle state is a pass, stated as what it
      is — not silently read as "filled".
