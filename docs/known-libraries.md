# Known libraries

Field libraries we know about. The list lives on this page,
in this repository, maintained by pull request. It is a
discovery list. It is not generated, and it is not the kit's
index: the index is `directory.json`, generated by
`tools/build_directory.py`, and today it catalogs the core
library only. Every library on this page is unindexed as far
as the wizard is concerned. Each library's own
`directory.json` is that library's catalog; this page only
points at them.

## What a listing means, and what it does not

A listing is a name-claim, not a review. It records that a
library exists at an address, under a named maintainer, at a
recorded pin. It is not an endorsement, not a vetting outcome,
and not evidence that anyone has read the library's modules.
The kit's provenance tiers make the same distinction for
connectors: a directory entry proves someone claimed the name,
nothing more.

Trust is earned the way `docs/library.md` describes, in three
separate claims that a listing never merges: read in full (the
installer's duty, in the installer's vetting log), rehearsed (a
run record at a hash), reviewed (a named human, not the author,
attesting at a pinned hash). A listed library can hold any of
those, none of those, or a different set per module. The entry
states what is recorded; where nothing is recorded, it says so.

## Getting listed

Open a pull request against this repository adding your
library's entry:

- the library's name and repository address;
- the URL of its `directory.json`, commit-pinned (a full
  commit hash in the URL, never a branch name, so the catalog
  it serves cannot move after the entry merges);
- its pin: the full commit hash the catalog was generated
  from. The `generated_from` in the catalog you point at must
  equal this hash;
- its maintainer, named (a person or agent, not an org
  label). The named maintainer opens the pull request or
  approves it in the thread: nobody is listed as a maintainer
  without saying so;
- whether it publishes an advisories file. A library with no
  advisories channel is listed as having none; that absence is
  a fact about the library, stated, not a defect hidden.

Name rules: a library id is first come, first listed, and it
is the prefix of every module id the library publishes
(`<library>/<module>`). An id that imitates `core/` or a
listed library is refused. The maintainer may refuse or remove
a listing for look-alike names, injection text in catalog
fields, unscrubbed personal data or credentials in the
library, or reported malicious behavior. A listing with no
module published within 90 days is dropped, so names are not
held empty.

Entries enter by reviewed pull request. The review checks the
entry, never the library's modules: the pinned link resolves,
the catalog parses, its `generated_from` matches the stated
pin, and `tools/kit_selfcheck.py --field <library-id>` passes
against a checkout at the pin. The result is recorded with the
entry. The three-claims work above is done per module, by
whoever does it.

Entries are checked mechanically at each core release (the
pin resolves, the package checks pass) and on report. When a
library moves, its entry is re-pinned by pull request; the
listed pin is the checked pin. An entry that fails a check
moves to the Removed section below, with the date and the
reason. If the reason is a safety problem, the library's
maintainer is asked to publish an advisory in that library's
own advisories channel — core advisories cover core modules —
because delisting does not reach anyone who already
installed the library.

A library that is not listed can still be installed: the
wizard's add library verb admits any library as unindexed,
with its own vetting entry and ticket. Listing is for
discovery. It is never a gate on use.

### Pending: the field pilot

The maintainer's own pilot library exists, and it is the
worked example of the format: one module,
`field/home-operations` (seasonal checklist, appliance
register, service log). Its repository is not public yet.
Publication is the maintainer's call, and it will be listed
here, with its address, when its repository is public. Its
status, stated the way an entry would state it: rehearsed at
4e62749 (run 15); changed since. Its brief-registration path
has never run. No review recorded. Its maintainer is the core
maintainer. Until it is listed, treat it as a template to
copy, not a catalog to browse.

Third-party libraries: none listed yet. Yours could be first.
The road in is the pull request above, and `CONTRIBUTING.md`
§3 states honestly what being first means right now.
