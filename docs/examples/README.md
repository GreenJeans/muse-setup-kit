# A worked example

Real artifacts from real rehearsals — not illustrations written
for this page. In rehearsal run 8 (see `docs/REHEARSALS.md`), a
fresh agent installed the Starter profile into a sandbox for a
fictional solo user ("Robin," freelance projects), ran it, and
then uninstalled it. Before uninstalling, it preserved these
files. In run 6, another fresh agent installed module 08 at the
Lite tier for a different fictional user and staged a skill
change; that produced the queue item and the staged proposal
below. In run 16, another fresh agent ran module 11's authoring
interview with a fictional solo user; that produced the soul
file.

Nothing here is edited except this page — and disclosed
conversions to setup-plan.md and soul.md so the examples teach
the current form: setup-plan.md's baseline lines are shown in
the `accumulating` form that run 8's own friction log produced
(conversion applied in v0.8), and with the qualified module
ids, library list, two-pin records, and module-attributed
baseline lines the library format made standard (conversion
applied in the library-format update, 2026-11-21). The runs'
own words — their approval quotes, their rehearsal strings,
their hashes — are unchanged. If an artifact shows a wart, the
wart shipped in the rehearsal and the friction log is what
fixed it (run 8's log is summarized in the REHEARSALS row).

- **`setup-plan.md`** — the plan the wizard wrote and the user
  approved before anything was installed: capabilities, the
  interview answers, module choices with their verification
  results, the deferred-check ledger, and the installed-file
  baseline (the queue and `JOBS.md` marked `accumulating` —
  inventoried, never hashed. The run's first draft hashed them,
  and ordinary use read as drift; its friction log is what
  produced the `accumulating` form, and the baseline is shown in
  that form).
- **`morning-brief.md`** — the first brief the install produced,
  failures-first, including the queue drill item the rehearsal
  planted and cleared.
- **`jobs.md`** — the scheduler-of-record after install: the
  brief job and the monthly spend check that rides it.
- **`queue-item.md`** — a staged skill-write item as it appeared
  in the decision queue (run 6): the diff inline, its hash, the
  base hash it is void against, and the smallest ask.
- **`staged-proposal.md`** — the proposal behind that item:
  verbatim evidence, the preference-order justification, and the
  routing note, exactly as the reviewer staged it.
- **`soul.md`** — the SOUL.md from run 16: a fresh agent ran
  module 11's authoring interview with a fictional solo user
  ("Casey," a freelance bookkeeper), drafted the file from the
  answers into the module's template, ran the module's
  checklist and linter against it, and wrote it on the
  persona's approval. Shown with two disclosed conversions:
  the sharing posture appears as its own bullet, the shape
  run 17's friction log gave the template (in the run's own
  file it sits inside the partner row), and one em dash in
  the first paragraph is a colon. Nothing else is edited.
  Kept as run, warts included: its Repair section names an
  "evening rundown" the file never defines (the morning check
  in its Modes table is the "Deadlines rundown"); its Warm
  mode exchange leads with facts rather than the human
  sentence the template's guidance describes — that is the
  persona's recorded answer, not the template's shape; its
  Modes table has no warm row; and its Disagreement and
  Repair sections keep, word for word, filled guidance lines
  the template shipped at run time. The template has since
  turned those lines into slots; the artifact is shown as it
  was written.
